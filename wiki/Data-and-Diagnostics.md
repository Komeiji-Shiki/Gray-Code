# 数据、记忆与诊断

[返回目录](Home.md)

本章介绍 GrayCode 的本地数据持久化机制、内容寻址去重存储、完整数据备份迁移，以及运行诊断与排障方法。

---

## 1. 本地存储架构

GrayCode 坚持**本地优先（Local-First）**原则，所有核心数据均保存在本地计算机：

- **SQLite 核心数据库**：用于结构化存储会话元数据、消息索引、配置项、记忆图谱与任务记录。
- **不可变内容寻址存储（CAS）**：历史消息的正文切片、大图附件、PDF 与请求快照按内容 Hash 唯一存储，相同内容跨会话自动复用，极大节省磁盘空间。
- **分支与快照**：分支会话共享相同的历史节点，分叉时仅记录新增差异，无需完整拷贝历史数据。

---

## 2. 数据备份与跨设备迁移

### 创建应用数据备份
进入 **设置 → 通用 → 程序数据备份**：
- **备份内容**：包含全部会话历史、上下文附件、记忆库、角色预设、渠道配置、MCP 设置与本地技能。
- **独立于源码**：备份仅包含应用配置与会话数据，不包含各工作区代码库本身的 Git 源码，保证备份包轻巧便携。

### 数据恢复
- 在新设备安装 GrayCode 后，进入数据管理界面，选择已有的备份文件即可一键还原。
- 系统会在恢复前自动校验数据完整性，并备份当前已有数据以防误操作。

## 3. 运行记录与实时诊断面板

当你需要深入了解模型交互细节或排查异常时，可以打开 **运行与诊断（Diagnostics）** 面板：

![运行与资源诊断界面](assets/diagnostics.png)

### 关键监控指标
- **输入图片与附件数**：检查发往大模型的实际多模态块数量。
- **请求内容项与工具声明数**：核对实际下发给模型的 Prompt 结构与工具目录。
- **活动任务与命令进程**：查看后台正在执行的子代理数量以及正在运行的终端进程。
- **缓存与连接状态**：实时监控 MCP 服务连接、事件队列与工具校验器缓存。

## 4. 常见问题排查（Troubleshooting）

| 异常现象 | 可能原因与建议排查步骤 |
| --- | --- |
| **模型回复说“看不到图片”** | 1. 检查当前渠道是否已勾选启用 **多模态（Vision）**。<br>2. 确认所选模型本身是否支持视觉输入。<br>3. 在诊断面板查看发往模型的请求是否包含图片数据块。 |
| **工具操作后无响应或超时** | 1. 检查终端命令是否在等待用户交互式输入（如 `npm init` 或 `sudo`）。<br>2. 检查 MCP 服务的超时时间设置是否过短。 |
| **文件修改未生效** | 1. 检查是否在 Diff 预览卡片上点击了确认“应用”。<br>2. 检查是否有未保存的本地编辑器草稿冲突。 |
| **外部 ACP 代理无法恢复会话** | 1. 确认该外部代理程序是否处于运行状态。<br>2. 检查启动命令与环境变量（如 API Key）是否正确配置。 |

> 提示：在命令行下运行 `npm run platform -- info` 或 `npm run platform -- verify` 可以直接检查本地数据库健康状态与一致性。

# 截图与坐标工具

[返回目录](Home.md)

GrayCode 提供 **Windows 窗口操作**、**内置浏览器**和**图像处理**工具。模型可以读取截图或控件信息，执行操作后再查看结果。

---

## 1. 电脑操作（Computer Use）

通过 Windows 原生宿主模块，模型能够直接操作宿主机上的桌面应用程序：

- **观察屏幕**：捕获指定应用窗口或当前桌面的高精度截图，并生成唯一的观察 ID 与像素尺寸元数据。
- **UI 自动化控件树**：对于复杂无障碍场景，支持按需读取 Windows UI Automation 控件树，获取清晰的元素层级与控件名称。
- **坐标映射与动作执行**：
  - 支持鼠标点击、双击、右键、拖拽、滚动。
  - 支持文本输入与快捷键组合（如 `Ctrl+A`、`Enter` 等）。
  - 自动处理高 DPI 屏幕与窗口缩放下的坐标对齐。
- **安全与人工接管**：用户随时可以通过鼠标键盘操作接管控制权，系统会在检测到人工介入时自动暂停操作。

## 2. 内置浏览器（Browser Use）

GrayCode 内置了轻量独立的浏览器环境，可供模型进行网页检索、表单填写、数据抓取与前端页面预览：

- **标签页生命周期**：支持创建标签、跳转 URL、前进、后退、刷新与关闭。
- **登录配置**：`profileId` 省略、空字符串或纯空白均使用当前账号的默认配置。
- **查看与接管分开**：显示/选择标签、鼠标被动经过页面不会中断模型。任务进行中，实际点击、滚轮、键盘、带按键拖动或明确点击“接管”会停止当前任务对该标签的操作，这一轮任务不能再操作它；下一轮任务自动交还，也可以在浏览器面板提前允许。任务结束后标签回到人工模式，之后用户的点击和键盘输入不算接管。接管错误不记录输入的按键内容。
- **混合交互模式**：
  - **视觉坐标模式**：模型使用截图图片的像素坐标进行点击或拖拽，工具自动换算为页面 CSS 像素，页面缩放和显示器像素缩放都已计入。截图结果的 `screenshot` 只含 `id`、图片 `width`/`height`（即坐标范围）和截图时的滚动位置 `scrollX`/`scrollY`。
  - **元素引用模式**：模型按快照返回的 `ref` 操作实际节点，`StaticText` 文字引用也可直接点击；工具使用文字范围和祖先元素定位。引用在同一文档内可跨动作、快照和分页复用。引用形如 `e12`、截图 ID 形如 `s3`，在整个桌面宿主内递增，不会与其他标签或已失效文档的编号重合。
  - **动作参数与回执**：只有 `navigate` 使用 `url`，其余动作按 `tabId` 操作当前页面；`type`、`press` 可以直接操作当前焦点，按键支持 `Esc`、`Return` 等别名和 `/`、`?` 等单个标点。`ref` 优先于同时传入的截图 ID。点击与悬停返回 `pointer.hit`，即实际命中的元素；目标被遮挡时仍尝试其可见位置，并用 `overlapped` 标记，元素没有坐标时尝试 DOM 点击并标记 `domClick`。悬停和滚动只改变观察位置，不按外部发送审批。
- **复杂页面检索**：`browser_read` 的 `snapshot` 支持 `query`（名称、值、描述或链接 URL 的不区分大小写片段）、`role`、`interactiveOnly`、`frameId` 和 `ref`。筛选在节点预算之前执行，可以找到长导航之后的正文、深层组件和 iframe 内的控件。正文按父子顺序返回，保留表头、单元格和段落的相邻关系。
- **自定义交互与内嵌图片**：`interactiveOnly` 同时包含原生控件、带点击监听的元素和独立设置 `cursor: pointer` 的区域，因此 JS 路由导航也能返回引用。快照中的内嵌图片与 Base64 数据 URL 只保留类型和省略标记，数据正文不占用节点字符预算。
- **截图引用**：坐标动作可以省略 `observationId`，此时使用最近截图。快照读取、SPA 路由、经过一段时间或本轮任务结束不会直接使截图 ID 失效；生成新截图后使用新 ID。页面变化后，调用方根据画面是否仍适用决定是否重新截图。
- **按需读取**：默认每次最多 250 个节点，可用 `maxNodes` 调整至 1–1000；另有约 60,000 字符的节点正文预算。`total` 表示本次筛选的匹配数，返回 `nextOffset` 时表示还有后续，保持筛选条件并把它传给 `offset`；限定 `ref` 的区域分页使用最新 `scopeRef`，即使区域根节点不在本页也能继续。页面内容变化后从头读取。个别超长字段返回片段并标记 `textTruncated`，可用更具体的 `query` 定位后面的文字；`partial: true` 表示有框架读取失败，不等于该框架没有内容。`frames` 只在页面含嵌入框架或读取失败时列出，单框架页面的框架 ID 已在节点的 `frame=` 行中。
- **表单与菜单**：`hover` 支持坐标或引用，可展开悬停菜单；`fill` 替换字段内容，空字符串清空，数值和日期字段遵循页面的原生格式；`type` 在当前焦点或给定引用处输入。`select` 根据 `values` 或 `labels` 设置原生下拉框，可多选，多选框可用空数组清空。`check` 使用 `checked` 设置复选框、单选框或开关的目标状态，状态已满足时不重复点击；单选框的取消通过选择同组其他选项完成。自定义菜单继续使用点击和按键，图表、画布使用截图坐标。
- **等待页面反馈**：`browser_read` 的 `wait` 使用 `query` 等待文字出现，`state: "absent"` 等待其消失；也可使用下文的 URL 或控件状态条件。文字条件可叠加 `role`、`frameId` 等筛选，默认等待 10,000 毫秒，`timeoutMs` 范围为 100–30,000 毫秒；支持取消和人工接管。返回 `conditionMet`、`timedOut` 和最后观察结果。条件满足表示观察到了指定状态，并不自动代表整项业务成功。
- **动作后的观察**：`browser_action` 默认 `after: "snapshot"`，返回页面状态和带 ref 的新快照，不附截图，避免长任务的上下文被截图占满；`after: "screenshot"` 返回截图（`data.screenshot` 与图片附件），适合画布或需要查看布局时使用；`after: "both"` 同时返回两种观察，`after: "none"` 只返回页面状态。带 `url` 或 `path` 新建标签时同样按 `after` 返回新页面的观察。`snapshotOptions` 支持 `compact`、`query`、`role`、`interactiveOnly`、`frameId`、`maxNodes`，不沿用动作前的 `ref` 或分页偏移，与 `after: "screenshot"` 或 `"none"` 同时使用会被拒绝。快照在 `data.snapshot`，新 ref 可直接供下次动作使用；续查仍通过 `browser_read`，保持同样的筛选条件。外层 URL/标题在观察后更新；两次观察间发生导航时省略已过期截图，不把旧图和新页面混在一起。
- **回执字段**：页面状态只有 `id`、`url`、`title`，加载中、出错、用户接管或其他任务占用时才出现 `loading`、`error`、`userControlled`、`otherTask`。动作回执另含 `pointer`、弹窗与文件选择框、本次动作新出现的下载和观察结果；失败回执的 `status` 为 `failed`（未执行，可修正后重试）或 `unknown`（可能已执行）。标签列表额外给出每个标签的 `profileId` 和可用的登录配置。
- **新标签回执**：动作期间从当前标签打开的新页面列在 `openedTabs`，包含请求地址 `requestedUrl`、可用的标签 `id`、URL/标题和 `status`（`opening`、`opened`、`failed`、`closed`）。截图与快照仍属于原标签，读取新页时使用新 ID。新页加载最多额外等待 1 秒；仍在初始化且没有 ID 的条目，以及回执返回后才打开的页面，可通过 `browser_tabs.list` 确认。不同来源标签的并发操作分别记录。
- **文档与绘制检查点**：动作后的文字快照等待主文档解析并读取同步布局，不依赖后台页面的绘制帧；导航导致读取失效时只重读观察，最多尝试 3 次、总计 5 秒。页面的异步业务数据继续使用 `browser_read.wait` 等待具体内容。滚动或点击后的截图仍等待新绘制帧。等待新页与观察期间，真实键鼠输入可立即接管。段落、标题等正文会按真实文本容器聚合碎片后再查询和分页，链接与控件继续保留各自的引用。
- **观察失败的恢复**：截图超时会说明停在哪个阶段（等待绘制帧、布局读取或图像采集）；纯观察超时可重试 `browser_read` 的 `screenshot`，也可先用 `snapshot` 检查页面状态。动作是否成功以工具结果为准，`observationError` / `snapshotError` 分别表示后续截图或快照失败，一项失败不丢掉另一项观察：此时重新读取，不要重复刚才的点击或提交，也不要求重新加载页面。

一个搜索流程可以带 `url` 新建标签，直接从返回的快照中找到搜索框，以返回的 `ref` 填写查询，直接向当前焦点发送 Enter，然后用 `wait` 等待结果标题或加载提示消失；需要看布局、图片或画布时再截图。读取论文、商品或数据表时再按 `role: "link"`、`role: "row"` 或具体文字筛选；结果链接返回浏览器实际识别的 URL。点击后先查看 `openedTabs`，使用新标签 ID 继续读取；延迟打开的页面可通过标签列表确认。文件上传和下载同样由 `tabId`、`ref` 定位控件，无需填写页面地址。

### 连续操作、弹窗与文件传输

- 连续填写已取得引用的字段时，中间动作可使用 `after: "none"`，最后一步再观察。默认返回快照。参数错误在派发前返回 `INVALID_ARGUMENTS`；已经派发但无法确认的输入保留 `unknown`，后续观察失败不会重复执行输入。
- 原生确认框和提示框返回 `dialog`，使用 `browser_action` 的 `action: "dialog"`、`accept` 和可选 `promptText` 处理。`browser_read` 的 `state` 可以随时查询弹窗、文件选择框和下载。弹窗等待处理时，动作回执不强行采集截图。
- 点击可见上传按钮后，隐藏文件控件会通过 `fileChooser.ref` 返回。将这个引用与 `paths` 交给 `browser_files.upload` 即可上传。
- 普通点击触发的下载会先保存在工具临时目录，动作回执或 `browser_read` 的 `state` 返回 `downloadId`。使用 `browser_files.download`、`downloadId`、`path` 和 `expectedHash` 保存，不必再次点击。直接用 `ref` 发起下载仍然支持；默认限制为 64 MiB，`maxBytes` 可显式调整，最高 1 GiB。未完成下载可取消，关闭标签会清理临时文件，工作区保存仍检查覆盖冲突和未保存编辑。
- 新标签直接接管 Chromium 创建的子页面，保留表单 POST、窗口名称及 opener 关系。导航等待主文档可读，最多等待 15 秒；超时后保留标签供继续观察，后台资源可能仍在加载。
- 人工接管停止自动输入，之后模型仍能读取页面与日志。进行中的读取仍可被真实键鼠或明确接管取消。同一标签访问按队列执行，独立标签的只读调用可并行。

### 长文本与定向观察

快照保留默认节点和字段预算。需要完整正文时，使用 `browser_read` 的 `action: "text"`、目标 `ref` 和可选 `maxChars`（默认 12000，最大 60000）；省略 `ref` 时读取整页正文。有 `nextChar` 时将它作为下一次 `startChar`，直到不再返回 `nextChar`。字符位置按 JavaScript 字符串偏移计算。

`logs` 读取控制台、脚本错误和网络日志，可用 `kind` 只看一类。网络日志只记录页面文档、接口请求（XHR、Fetch、EventSource、WebSocket）和状态码 400 以上或加载失败的资源，失败记录带请求地址；成功加载的图片、字体、样式和脚本不进入日志，避免挤掉控制台错误。

`wait` 除文字出现或消失外，还可以传入 `url` 等待精确地址，或 `urlChanged: true` 等待地址不同于本次等待开始时的值。控件等待使用 `ref` 与 `state: "visible" / "hidden" / "enabled" / "disabled" / "checked" / "unchecked"`。这些状态通过目标节点读取，不必轮询整页。筛选快照附带少量所属区域信息，用来区分同名按钮；完整快照面板同时展示聚合正文和控件状态。

工具回执保留在会话历史；旧会话中的截图元数据和动作回执字段继续可以显示。流式下载的恢复快照通过现有内容对象记录分块引用，旧的字节快照继续可读；备份和删除会话沿用原有记录路径。

页面正文、链接和提示都是网站资料。工具不会把网站内容当作新的用户授权。截图、元素引用、账号权限、人工接管和动作回执仍沿用同一套机制；工具参数和说明的更新会使升级后的工具请求前缀变化一次，历史消息与图片顺序保持不变。

## 3. 图像处理工具（Image Tools）

在视觉分析和多模态流程中，系统内置了基于高性能 Sharp 引擎的图像处理能力：

- **结果预览**：图像工具返回的图片显示为缩略图，点击后进入附件查看器，可缩放、旋转并关闭返回对话。右键图片可复制图片、保存原图、显示原始尺寸或适应窗口，工具栏也提供复制入口，支持 Ctrl+C / Cmd+C。复制使用原始像素生成 PNG，保存保留原附件格式与内容；查看器中的缩放、旋转和平移不改变复制或保存的图片。主聊天与子代理窗口各自显示所属任务的图片。
- **任务状态与取消**：等待执行、处理中、部分成功和取消分别显示。取消按钮作用于对应图像任务，失败时显示具体原因；已完成的图片仍可查看。
- **高效单链处理**：图像裁剪、等比缩放、旋转与格式转换在同一处理管道中完成，避免反复编解码损失画质与时间。
- **格式支持**：全面支持 PNG、JPEG、WebP、AVIF、TIFF、GIF 与 SVG 等格式。
- **透明度保持**：旋转或转换 PNG/WebP 等支持透明通道的图像时，完整保留透明背景信息。

### 元素引用的复用

同一文档中的元素引用可以跨动作、文字快照和分页使用。文字、链接、输入值、焦点和选中状态变化时，引用仍指向原来的 DOM 节点；主文档换页或重载、目标节点被删除后需要重新读取。点击会报告当前命中的元素，调用方结合动作结果决定下一步。

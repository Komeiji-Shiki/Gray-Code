# 截图与坐标工具

[返回目录](Home.md)

GrayCode 提供 **Windows 窗口操作**、**内置浏览器**和**图像处理**工具。模型可以读取截图或控件信息，执行操作后再查看结果。

---

## 1. 电脑操作（Computer Use）

通过 Windows 原生宿主模块，模型能够直接操作宿主机上的桌面应用程序：

- **观察屏幕**：捕获指定应用窗口或当前桌面的高精度截图，并生成唯一的观察 ID 与像素尺寸元数据。
- **UI 自动化控件树**：对于复杂无障碍场景，支持按需读取 Windows UI Automation 控件树，获取清晰的元素层级与控件名称。
- **坐标映射与动作执行**：
  - 支持鼠标点击、双击、右键、拖拽、滚动。
  - 支持文本输入与快捷键组合（如 `Ctrl+A`、`Enter` 等）。
  - 自动处理高 DPI 屏幕与窗口缩放下的坐标对齐。
- **安全与人工接管**：用户随时可以通过鼠标键盘操作接管控制权，系统会在检测到人工介入时自动暂停操作。

## 2. 内置浏览器（Browser Use）

GrayCode 内置了轻量独立的浏览器环境，可供模型进行网页检索、表单填写、数据抓取与前端页面预览：

- **标签页生命周期**：支持创建标签、跳转 URL、前进、后退、刷新与关闭。
- **登录配置**：`profileId` 省略、空字符串或纯空白均使用当前账号的默认配置。
- **查看与接管分开**：显示/选择标签、鼠标被动经过页面不会中断模型。实际点击、滚轮、键盘、带按键拖动或明确点击“接管”会停止模型对该标签的操作；需要用户重新允许后才能恢复。接管错误会提示触发的事件类型，不记录输入的按键内容。
- **混合交互模式**：
  - **视觉坐标模式**：模型直接基于网页截图的像素坐标进行点击或拖拽。
  - **元素引用模式**：模型读取浏览器无障碍树，按真实的控件名称、角色和状态操作；读取快照会更新引用，但不会使未改变页面的截图观察 ID 失效。
- **复杂页面检索**：`browser_read` 的 `snapshot` 支持 `query`（名称、值、描述或链接 URL 的不区分大小写片段）、`role`、`interactiveOnly`、`frameId` 和 `ref`。筛选在节点预算之前执行，可以找到长导航之后的正文、深层组件和 iframe 内的控件。正文按父子顺序返回，保留表头、单元格和段落的相邻关系。
- **按需读取**：默认每次最多 250 个节点，可用 `maxNodes` 调整至 1–1000；另有约 60,000 字符的节点正文预算。`total` 表示本次筛选的匹配数，`returned` 表示本次返回数，`nextOffset` 用于续查。保持筛选条件并把 `nextOffset` 传给 `offset`；限定 `ref` 的区域分页使用最新 `scopeRef`，即使区域根节点不在本页也能继续。页面内容变化后从头读取。个别超长字段返回片段并标记 `textTruncated`，可用更具体的 `query` 定位后面的文字；`partial` 表示有框架读取失败，不等于该框架没有内容。
- **表单与菜单**：`hover` 支持坐标或引用，可展开悬停菜单；`fill` 替换字段内容，空字符串清空，数值和日期字段遵循页面的原生格式；`type` 在当前焦点或给定引用处输入。`select` 根据 `values` 或 `labels` 设置原生下拉框，可多选，多选框可用空数组清空。`check` 使用 `checked` 设置复选框、单选框或开关的目标状态，状态已满足时不重复点击；单选框的取消通过选择同组其他选项完成。自定义菜单继续使用点击和按键，图表、画布使用截图坐标。
- **等待页面反馈**：`browser_read` 的 `wait` 必须提供 `query`，默认等待文字出现，`state: "absent"` 等待其消失。可叠加 `role`、`frameId` 等筛选，默认等待 10,000 毫秒，`timeoutMs` 范围为 100–30,000 毫秒；支持取消和人工接管。返回 `conditionMet`、`timedOut` 和最后观察结果。条件满足表示观察到了对应文字状态，并不自动代表整项业务成功。
- **动作后的观察**：`browser_action` 默认 `after: "screenshot"` 保持截图行为；`after: "snapshot"` 只返回新快照和元素引用，`after: "both"` 同时返回两种观察。`snapshotOptions` 支持 `compact`、`query`、`role`、`interactiveOnly`、`frameId`、`maxNodes`，不沿用动作前的 `ref` 或分页偏移。快照在 `data.snapshot`，新 ref 可直接供下次动作使用；续查仍通过 `browser_read`，保持同样的筛选条件。外层 URL/标题在观察后更新；两次观察间发生导航时省略已过期截图，不把旧图和新页面混在一起。
- **新标签回执**：动作期间从当前标签打开的新页面列在 `openedTabs`，包含请求地址 `requestedUrl`、可用的标签 `id`、URL/标题和 `status`（`opening`、`opened`、`failed`、`closed`）。截图与快照仍属于原标签，读取新页时使用新 ID。新页加载最多额外等待 1 秒；仍在初始化且没有 ID 的条目，以及回执返回后才打开的页面，可通过 `browser_tabs.list` 确认。不同来源标签的并发操作分别记录，重复工具调用保留打开事实而不会再次点击。
- **文档与绘制检查点**：动作后的文字快照等待主文档解析并读取同步布局，不依赖后台页面的绘制帧；导航导致读取失效时只重读观察，最多尝试 3 次、总计 5 秒。页面的异步业务数据继续使用 `browser_read.wait` 等待具体内容。滚动或点击后的截图仍等待新绘制帧。等待新页与观察期间，真实键鼠输入可立即接管。段落、标题等正文会按真实文本容器聚合碎片后再查询和分页，链接与控件继续保留各自的引用。
- **观察失败的恢复**：截图超时会说明停在哪个阶段（等待绘制帧、布局读取或图像采集）；纯观察超时可重试 `browser_read` 的 `screenshot`，也可先用 `snapshot` 检查页面状态。`browser_action` 的 `status` 表示动作结果，`observationError` / `snapshotError` 分别表示后续截图或快照失败，一项失败不丢掉另一项观察：此时重新读取，不要重复刚才的点击或提交，也不要求重新加载页面。

一个搜索流程可以先截图了解网站，再用 `snapshot` 查找搜索框，以返回的 `ref` 填写查询，使用最新截图的 `observationId` 按 Enter，然后用 `wait` 等待结果标题或加载提示消失。读取论文、商品或数据表时再按 `role: "link"`、`role: "row"` 或具体文字筛选；结果链接返回浏览器实际识别的 URL。点击后先查看 `openedTabs`，使用新标签 ID 继续读取；延迟打开的页面可通过标签列表确认。

页面正文、链接和提示都是网站资料。工具不会把网站内容当作新的用户授权。截图、元素引用、账号权限、人工接管和动作回执仍沿用同一套机制；本次工具参数和说明扩充会使升级后的工具请求前缀变化一次，历史消息与图片顺序保持不变。

## 3. 图像处理工具（Image Tools）

在视觉分析和多模态流程中，系统内置了基于高性能 Sharp 引擎的图像处理能力：

- **结果预览**：图像工具返回的图片显示为缩略图，点击后进入附件查看器，可缩放、旋转并关闭返回对话。右键图片可复制图片、保存原图、显示原始尺寸或适应窗口，工具栏也提供复制入口，支持 Ctrl+C / Cmd+C。复制使用原始像素生成 PNG，保存保留原附件格式与内容；查看器中的缩放、旋转和平移不改变复制或保存的图片。主聊天与子代理窗口各自显示所属任务的图片。
- **任务状态与取消**：等待执行、处理中、部分成功和取消分别显示。取消按钮作用于对应图像任务，失败时显示具体原因；已完成的图片仍可查看。
- **高效单链处理**：图像裁剪、等比缩放、旋转与格式转换在同一处理管道中完成，避免反复编解码损失画质与时间。
- **格式支持**：全面支持 PNG、JPEG、WebP、AVIF、TIFF、GIF 与 SVG 等格式。
- **透明度保持**：旋转或转换 PNG/WebP 等支持透明通道的图像时，完整保留透明背景信息。

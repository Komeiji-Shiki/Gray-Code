# LifeBook 记忆迁移

LifeBook 导入使用独立资料库。导入完成后，在记忆管理的“导入资料库”查看原文件，或进入“查看与编辑记忆”核对正文、来源和实际图谱关系。初始条目为“尚待核对”，资料库自动召回关闭。

包含独立资料库的数据库使用存储格式第 8 版，需要支持这项功能的 GrayCode 打开或恢复；旧客户端会通过版本检查明确拒绝。

原始档案与可编辑记忆分别保存：Markdown、JSONL、图片、SQLite 索引、Kuzu 数据库和 WAL 均按字节保留。文件可以完整下载，读取后会校验 SHA-256。编辑记忆会生成新的修订，不覆盖原始档案。

## 执行导入

先准备稳定的 LifeBook 数据目录，建议使用停止写入后的完整副本。来源与 GrayCode 目标数据目录必须独立，不能相互包含。导入命令不会调用模型，也不会切换日常应用的数据目录。

若存在 `.graphiti.kuzu`，先使用与源数据库兼容的 Python Kuzu 包导出完整图谱；脚本在临时副本上恢复 WAL，不以写入模式打开原库。输出文件放在原目录之外：

```powershell
python scripts/export-lifebook-graph.py C:\Migration\lifebook\.graphiti.kuzu C:\Migration\graph-export.json
npm run build:platform
node apps/server/dist/main.cjs --data C:\GrayCode-Import import-lifebook C:\Migration\lifebook --graph-export C:\Migration\graph-export.json --actor owner --name "LifeBook 导入资料库"
```

没有 Kuzu 图谱的目录可以省略 `--graph-export`。`--actor` 指定目标账号，默认 `owner`。目标应用使用其他账号时，需填写其真实账号编号。

若使用 `graycode-source-snapshot` 第 1 版清单，可传入 `--source-manifest <json>`。清单的每个文件需要包含 `path`、`bytes`、`sha256`、`modifiedAt`、`createdAt`，并与来源的完整文件集合一致。导入会保留清单中的原始时间，避免把复制时间当成原文件创建时间。

导入先保存并校验全部原文件，再以同一个存储事务发布记忆和资料库目录。发布前会再次检查来源文件集合与内容；发现变化就停止发布。相同来源再次导入会校验已有文件，不覆盖人工编辑，也不会恢复已经删除的记忆。

## 如何转换

| 来源 | 可编辑与检索内容 | 原始信息 |
| --- | --- | --- |
| Markdown | 保留连续文本范围，分段创建条目 | 全部换行和原字节保留 |
| JSONL 对话 | 用户与助手发言分别标注；图片关联到对应来源 | 头尾记录、附加字段、模型信息仍在原日志中 |
| Kuzu 实体和事实 | 使用真实连接建立实体、事件和事实依赖，保留事实有效期 | 全表导出、向量、内部编号及数据库原件均保留 |
| 图片与其他文件 | 原文件预览或下载，不推测图片含义 | 不压缩、不转码 |
| 旧检索索引 | 原样保存供核对与回退 | 不将模型和前缀未知的旧向量混入新索引 |

非标准对话行按原文保留。缺失的图片和事件引用会在迁移说明中列出数量，原编号仍留在档案中。迁移不会补造已经丢失的文件。

## 核对与召回

先在记忆编辑器核对条目，将确认状态改为“已确认”并保存，再在资料库勾选“已核对，允许在私人对话中自动召回”。资料库仅加入该账号的私人真实记忆范围，群聊和角色剧情保持独立。全局记忆开关、每轮条数和 token 预算继续生效。

人工浏览按页显示，长正文先显示预览，打开后读取完整内容，不受模型召回 token 预算截断。可以单独筛选待核对、已确认或存在争议的条目；“全部条目的最新修订”也包含未来生效、已过期或依据失效的条目。相关性搜索继续使用原有关键词与语义检索。关系图和修订记录可以打开确切历史版本，回到最新修订后再修改。

确认单个条目不会自动启用整个资料库。启用资料库也不会把待核对、存在争议或已经失效的条目变成已确认事实。后续聊天的自动提取继续写入个人、项目或群组范围，不追加到导入资料库。

“导出当前范围”导出正文、来源和修订的记忆交换归档；完整原始文件使用应用备份保存。选择性恢复“长期记忆”时会包含资料库的原始文件组，避免只有条目而缺少附件。

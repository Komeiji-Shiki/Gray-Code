# 记忆、桌宠与屏幕感知配置

[返回目录](Home.md)

GrayCode 使用 Markdown 文件保存跨会话记忆，保留导入资料库的检索与管理，并提供 Live2D 桌面伴侣交互及屏幕感知能力。

---

## 1. 文件记忆与导入资料库

### 文件记忆

在 **设置 → 记忆** 中控制记忆总开关，或点击 **打开记忆目录** 查看数据目录下的 `memory/`。便携版使用 `portable-data/memory/`，记忆文件随数据备份导出与恢复。

| 目录 | 内容与访问范围 |
| --- | --- |
| `memory/global/` | 主人账号跨项目使用的个人偏好与协作约定 |
| `memory/projects/<目录名>-<hash12>/` | 主人账号在当前项目使用的目标、约束和外部资料线索 |
| `memory/bots/<discord\|qq>-[dm-]<频道编号>/` | 当前 Bot 频道共享的记忆，私聊目录带 `dm-` 前缀 |
| `memory/characters/<根会话 ID>/` | 当前角色故事的剧情事实、角色状态与故事偏好 |

普通主人会话与伙伴会话使用全局记忆，有工作区时同时使用项目记忆；Bot 会话只使用本频道目录，角色会话只使用本故事目录。子代理继承根会话的记忆范围。Bot 频道中的内容对频道参与者可见，访客写入仍需具有文件写入权限。

每个目录的 `MEMORY.md` 是索引，一条记忆占一行：

```markdown
- [协作偏好](collaboration.md) — 讨论方案时需要说明约束与原因
```

每条记忆单独放在 Markdown 文件中，开头使用 frontmatter：

```markdown
---
name: collaboration
description: 讨论方案时需要说明约束与原因
type: feedback
---

在开始修改前说明设计约束、下一步操作及选择该方案的原因。
```

普通记忆的 `type` 使用 `user`、`feedback`、`project` 或 `reference`，分别记录个人偏好、协作方式及原因、持续目标与约束、外部资料线索。角色故事记忆只需 `name` 和 `description`，不需要 `type`。文件格式由模型按指引维护，宿主不解析 frontmatter。

模型通过 `read_file`、`list_files`、`write_file`、`apply_diff` 等现有文件工具读写，并在新增或删除记忆时同步维护 `MEMORY.md`。只读模式只提供读取指引。适合保存后续会话仍有价值的内容；代码和 Git 历史已记录的信息、秘密及仅对本次对话有效的细节不应重复保存。

当前会话记忆目录内的文件写入直接应用，不等待文件审阅；关闭自动保存也一样。完成后的工具卡片仍可打开修改详情。

会话首次组装提示时读取各目录索引，并把它们作为参考快照放在历史之前；快照随该回合消息保存，会话中改写文件和重启应用都不会刷新它，只有记忆目录变化或开始新的会话才重新读取。单份索引超过 200 行或 25 KB 时，保留上限内的完整行并提示整理。模型需要详情时主动读取对应文件。记忆只提供参考，不授予权限，当前用户明确表达的要求优先。

### 导入资料库与旧记录

**资料库 → 长期记忆** 保留资料导入、主题浏览、检索、修订、删除、导出、恢复、向量配置和任务列表。启用的真实资料库可由模型主动调用 `memory_topics`、`memory_search`、`memory_read` 检索；资料库不再每轮自动召回，对话结束后也不再自动抽取记忆。摘要整理和向量任务继续可用。

旧数据库记录保持原格式，可在现有界面中浏览、导出和删除，本次改造不把它们迁移成文件，也不删除旧记录。工程日志及专用记忆写入工具已移除，新记忆统一按文件指引保存。

## 2. 桌宠与 Live2D 伴侣配置

在普通对话中打开 **陪伴配置**，依次完成 **角色卡、桌宠、屏幕感知、定时问候**。每段会显示是否已配置和当前选择，相关表单可以就地展开。角色卡选择、人设字段和交流偏好使用当前对话的陪伴配置。

**设置 → 陪伴** 集中管理全局的 Cubism Core 运行库、桌宠显示与缩放，以及默认识图渠道和模型。模型与动作说明在陪伴配置的桌宠段内管理：

- **模型导入**：支持导入标准的 Live2D Cubism 模型资源目录（包含 `.model3.json`、贴图及动作定义文件）。如果尚未导入 Cubism Core，同一导入界面会提供 Core 文件选择和 [Cubism SDK for Web 官方下载页](https://www.live2d.com/download/cubism-sdk/download-web/) 链接；选择本机的 `live2dcubismcore.min.js` 后即可继续导入模型。应用不会自动下载或打包 Core。
- **参数与表现调节**：动作、表情、视线和参数分别控制，可以同时播放，并分别恢复。可调整缩放、朝向，以及思考、工作、等待和错误等任务状态对应的动作。
- **现代模型表现**：播放支持模型声明的乘算色、屏幕色和 BlendShape 参数。形变由导入的 Cubism Core 计算，颜色在实际绘制与遮罩路径中处理。
- **动作说明**：可以给动作、表情补充一句语义描述，例如“开心挥手”。首次绑定时保存固定的动作词表及其指纹；之后修改说明，陪伴设置会提示“动作词表有更新”。点击“同步”才会更新当前对话使用的词表，当前对话的提示词缓存会重建一次。普通保存保留已绑定的词表；旧配置没有指纹时按已同步显示。
- **空闲与停止**：没有模型指令时仍低频更新眨眼、呼吸和物理。导入模型的 Idle 动作可以作为待机映射。“减少动画”或“停止”继续按用户设置生效。
- **互动和声音**：支持鼠标跟随和模型声明的点击区域，可为点击区域指定动作。动作音效、系统语音需要在设置中开启；语音使用系统可用声音，口型按模型声明的口型参数进行近似同步。

桌宠采用“手动高于模型、模型高于任务”的通道优先级。`cancel` 释放允许撤销的通道，不再额外占用控制时间；`resume` 释放当前模型控制并恢复任务动画。用户主动停止后，需要用户在界面恢复，模型不能自行解除。

普通对话的陪伴设置可以选择角色卡、人设字段和代表该角色的桌宠。自动人设来源优先读取 `personality`，为空时读取 `description`；也可以明确选择描述或两者组合。绑定后模型知道桌宠的动作词表，回复中可写 `<pet motion="动作ID" expression="表情ID"/>`，两项可以同时使用或只给一项。标签不会显示为聊天文字，也不需要另一次模型请求；需要实际播放回执或精细参数控制时仍使用 `pet_control`。

桌宠工具只在有对应宿主能力的对话和角色模式提供，显示或隐藏不会改变工具目录。默认自动执行桌宠动作；用户明确设置的审批、禁用规则仍然生效，行内标签也遵守这些选择。陪伴设置里的“定时问候”就地复用自动任务表单，使用当前对话和模型，选择触发时间后保存。

### Clawd 独立桌宠联动

GrayCode 可以向同一电脑上运行的 [Clawd-on-Desk](https://github.com/rullerzhou-afk/clawd-on-desk) 发送任务状态。使用支持 [Custom HTTP Agent](https://github.com/rullerzhou-afk/clawd-on-desk/blob/main/docs/guides/custom-agent-http.md) 的 Clawd 版本。

1. 启动 Clawd，在 **Settings → Agents** 添加 GrayCode 的可执行文件或安装目录，扫描后注册应用，复制生成的 **Agent ID**。
2. 打开 GrayCode 的 **设置 → 集成与连接 → Clawd 独立桌宠联动**，填写 Agent ID、启用联动，再点击 **保存全部**。
3. 点击 **检查连接**。收到确认后，在 GrayCode 开始任务，Clawd 就会显示对话名称，以及思考、工具执行、等待确认、完成或失败状态。对话自动命名或手动重命名后，桌宠中的名称也会更新。取消任务会结束相应状态，不显示完成庆祝。

不同对话使用独立的会话标识，同一对话的连续任务更新同一个会话。名称取自 GrayCode 已保存的对话标题，通过 Clawd 的 `session_title` 字段上报；没有标题时沿用 Clawd 的工作区名称显示。仅发送状态、会话标识、对话标题、工作区路径和工具名称等元数据，不发送消息正文、工具参数或凭据。工具审批和问题回答仍在 GrayCode 中处理。连接检查确认 Clawd 接收了状态；勿扰模式可能抑制可见动画。

联动通过本机 `~/.clawd/runtime.json` 自动发现端口。Clawd 未运行时不阻塞 GrayCode；恢复连接后同步最新状态，运行中的任务定期报告状态。关闭联动或退出 GrayCode 时结束已报告的会话。Web 模式连接的是 **GrayCode 服务端所在电脑** 的 Clawd。旧设置保持未启用，备份恢复后需重新启用并确认本机注册信息。

## 3. 屏幕感知（Screen Perception）

屏幕感知使用独立的小模型识图，再把用户正在做什么、当前进度与重要变化概括为文字，发送到选定的普通对话。主模型沿用该对话的渠道和模型选择，新截图只用于识图，不会逐张加入主对话历史。

在陪伴配置的屏幕感知段中选择采集窗口或显示器，以及支持图片输入的识图渠道和模型。摘要自动发送给当前陪伴对话，无需另选目标对话。屏幕感知仍只有一份全局配置，同一时间服务一个对话；在另一段陪伴对话中保存配置会更换目标。默认识图渠道和模型也可以在“设置 → 陪伴”中修改。

可以手动采集并预览后发送，也可以设置间隔自动识别。**打开此陪伴对话时自动开启** 默认关闭；启用后，正常打开对应陪伴对话会开始本次采集。未启用时继续通过“开启本次屏幕感知”手动开始。采集期间显示常驻状态指示，可一键停止；启动失败后的恢复界面不会自动采集。从备份恢复屏幕感知配置时，自动开启开关会关闭，确认配置后可以重新启用。

每次截图先在本地计算缩小后的画面特征，变化很小时跳过识图请求。识图模型只接收当前截图与上一次活动摘要，避免重复发送整段聊天记录。勾选“没有值得交流的变化时，允许模型看过不回”后，识图模型可以选择保持安静；需要交给主模型判断时，主模型也可以使用静默回执。

面板分别显示识图请求和主对话任务的真实渠道用量。可选参考单价只用于估算识图费用，主对话用量单列，缺失的渠道用量标为未知。旧发送记录仍按当时的主对话价格解释。

采集次数包含预览与画面未变化而跳过的采集，到达本次上限后不再继续。停止采集会取消进行中的识图并清除预览；已经发送的主对话任务可以单独停止。窗口关闭、进程身份或显示器坐标变化时，需要重新选择目标。

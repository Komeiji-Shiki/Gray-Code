# 记忆、桌宠与屏幕感知配置

这些功能有各自的开关：显示桌宠、采集屏幕、聊天引用记忆、后台提取记忆可以分别配置。界面中的参数说明会解释数值影响，修改后通过对应的保存按钮应用。

## 两种记忆的用途

长期记忆按个人、项目、群组和真实资料／角色剧情隔离，保存事实、偏好、经验及其来源。主题目录与分层摘要用于逐步查阅，修订保留历史；模型可直接搜索明确的问题，再按编号展开有关记录和来源。

主题目录按需加载，超过一页时可以继续加载同级主题。模型的 `memory_topics` 使用返回的 `nextCursor` 续页；如果目录在两页之间发生修改，需要从当前主题重新读取。返回 `requiredTokenBudget` 表示单个目录条目超过预算，增加到该值后可沿同一游标继续，避免反复获取空页。

长正文或来源可以由 `memory_read` 的 `page` 分段查看，使用已读取的记忆编号与版本；填写 `sourceId` 时读取其对应原文。每页给出 `nextOffset` 和总长度，模型沿返回位置继续。分页保留原记忆依据，来源被纠正或删除后，旧页不再作为当前有效内容返回。

工程记忆日志通过 `memory_wake`、`memory_note` 等工具维护全局或工作区约定。它的唤醒行数和分页设置独立于长期记忆的召回预算。

| 长期记忆设置 | 当前默认值 | 数值影响与使用场景 |
| --- | --- | --- |
| 最多引用条数 | 5 | 每轮自动引用的相关条目数上限。短条目涉及多个主题时可提高；还受 token 预算限制。 |
| 记忆上下文预算 | 1200 估算 token | 包含自动加入的记忆文字及说明。较低值节省上下文；复杂项目可尝试 2000～4000，并在实际请求中检查选入内容。 |
| 自动提取 | 关闭 | 开启后，对话完成会在所选范围中调用整理模型，产生额外请求。与聊天自动引用开关独立。 |
| 整理输出上限 | 12288 token | 包括渠道计入的思考内容。过低可能截断结构化结果；较高值允许更多整理输出，并不表示每次都会用满。 |
| 嵌入维度 | 不指定 | 留空使用服务返回值。仅填写模型实际支持的维度；较低维度减少索引空间，也可能影响相似内容的区分。 |
| 查询／正文前缀 | 不指定 | 只按嵌入模型文档填写。修改模型、维度或前缀后重建索引，旧向量不与新配置混用。 |

条数和预算同时生效。提高上限只允许选入更多内容，不保证每轮都能找到那么多相关条目。嵌入服务不可用时仍可用关键词检索，实际检索方式和失败原因以返回结果为准。

工程日志默认一次唤醒 96 行，单条最多 280 UTF-8 字节，每页最多 20000 字符或 500 行。常见汉字通常占 3 字节，超长条目会拒绝保存。减少分页大小会增加读完全部内容所需的工具调用，不会减少总内容。

## 按需读取和精确修订

在“资料库 → 长期记忆”中选择一条记录，可以编辑正文、确认状态、主题、属性和有效时间。切到“查看关系”可以看到实际的来源与依赖，以及以这条记忆为依据的派生记录。点击来源显示原文；点击相邻记忆继续查看；点击当前节点返回编辑。草稿不会因为切换视图而丢失。

关系图按窗口宽度使用横向或纵向布局，支持缩放。历史或失效的修订用虚线标明；“待核对”和“有争议”保留各自标识。大型关系按数量限制分批查看，可通过相邻节点继续展开。连线只代表已经保存的依赖，不根据关键词相似性推测关系。

`memory_topics` 返回主题路径、数量和摘要编号；长摘要可继续用 `memory_read` 展开。`memory_read` 的 `omitted` 标明哪些正文或来源因预算、条数上限而省略，并给出估算大小。可减少同批编号或提高 `tokenBudget` 后重读。失效或删除的内容不会因为提高预算而恢复。

`memory_revise` 保留稳定编号、来源校验和 `expectedVersion` 冲突检查，支持三种互斥的文字修改方式：

| 方式 | 参数 | 场景 |
| --- | --- | --- |
| 局部替换 | `oldText`、`newText` | 更改端口、修正一句话。原文须唯一匹配，`newText` 为空可删除该片段。 |
| 末尾追加 | `append` | 增加一条有关说明，需要换行时在文字中包含换行。 |
| 完整修订 | `text` | 需要重新组织整条记忆时使用。 |

局部修改只需让模型输出变动的片段。找不到原文、出现多个匹配或版本过期时，会要求重新读取，不会猜测要改哪一处。任何修订仍会使依赖旧版本的摘要失效。

精确补丁和按需展开的交互参考了 [Nocturne Memory 工具说明](https://github.com/Dataojitori/nocturne_memory/blob/ffb5c709ba9785977b48a974082e330d70410f74/docs/TOOLS.md)。GrayCode 继续使用现有的来源、时效、权限和删除传播规则。

## 桌宠与 Live2D

先导入包含全部引用文件的资源目录，选择模型并预览。Live2D 还需要从官方 SDK 导入本地 Cubism Core。动作名称、表情和参数范围来自实际模型。

| 设置 | 影响 |
| --- | --- |
| 缩放 0.4～3 倍 | 1 倍为基础尺寸；较小值节省空间，较大值便于看清细节，并可能增加绘制负担。 |
| 预览持续时间 0.1～120 秒 | 控制多久后恢复正面，不改变动作速度。看表情可用 2～6 秒，长动作可延长。 |
| 观察方向 | 0° 向上、90° 向右、180° 向下、270° 向左，每格 22.5°。v1 精灵图不支持定向视线。 |
| 模型参数 | 从模型默认值附近小幅调整。数值的实际含义和转动幅度由素材决定，不同模型不能套用同一组值。 |
| 减少动态效果 | 显示姿势画面，适合减少持续动画或节省资源。 |
| 任务动画映射 | 保存所选 Live2D 后，为待机、运行、等待、审查和失败指定模型已有动作。未指定时不为该状态发起新动作。 |

预览只影响设置中的画面。显示位置、缩放、动画映射等需要保存并应用；更换资源和跳转屏幕感知时，会检查未保存的选择。

## 屏幕感知与电脑面板

偶尔询问画面可选择手动采集和先预览；持续关注进度可选择间隔采集。自动发送会直接发起模型任务，因此较短间隔会增加截图、上下文和请求开销。

采集间隔允许 1～86400 秒。下载或构建进度可先使用 30～60 秒，缓慢变化可使用几分钟。目标对话仍有任务时，自动发送模式等待下次采集。采集次数上限包含预览采集，达到后停止继续采集；停止采集与取消已经发出的任务有独立按钮。

电脑面板以截图为主要内容，控件树和文字输入放在独立标签。截图按需刷新，可选择标准、清晰、精细三档最长边像素，以及适应面板或原始像素显示。操作完成会重新读取画面；若动作已执行但后续捕获失败，界面会区分两者。这里手动查看的截图不发送给模型。

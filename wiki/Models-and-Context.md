# 模型、图片与上下文

[返回目录](Home.md)

本章介绍 GrayCode 的模型渠道协议支持、上下文优化、Prompt Caching 保持机制以及视觉模型配置。

---

## 1. 模型渠道与协议适配

GrayCode 原生支持主流大模型协议，并在协议层做了深度适配：

| 协议类型 | 适用渠道 / 服务商 | 工具调用与多模态特点 |
| --- | --- | --- |
| **OpenAI Chat Completions** | DeepSeek、SiliconFlow、OneAPI、Moonshot 等 | 标准 `tool_calls` 与兼容格式，多模态通过标准 `image_url` 传入 |
| **OpenAI Responses** | OpenAI 官方最新 Responses 接口 | 采用最新输入块结构，提供结构化与多模态流式响应 |
| **Anthropic** | Claude 3.5 / 3.7 全系列 | 官方 Content Blocks（含 tool_use / tool_result 与原生多模态传递） |
| **Gemini** | Google Gemini 1.5 / 2.0 / Flash | 原生多模态部件与 Function Calling 格式 |

---

## 2. Prompt Caching（提示词缓存）与上下文稳定性

大语言模型的 Prompt Caching 能大幅降低长上下文对话的延迟与 API 费用。GrayCode 在架构设计上高度注重前缀稳定性：

- **确定性请求前缀**：系统提示词（System Prompt）、工具声明（Tool Declarations）和历史消息按稳定顺序组装。
- **追加式交互**：新产生的工具调用结果、截图和用户输入均追加在末尾，不会在会话中途随意重排历史项，确保尽可能多地命中服务商的 Prompt Cache（如 Claude Caching、DeepSeek 缓存）。
- **增量读取**：前端和执行器交互采用增量游标同步历史，避免频繁重复序列化庞大的历史记录。

## 3. 工作区上下文自动注入

在每次向模型发送指令时，GrayCode 可以在系统上下文中自动附带当前工作区的精简状态，以便模型快速感知工程全貌：

进入 **设置 → 上下文（Context）** 可自定义注入策略：

- **文件树深度**：控制自动附带的目录树层级（默认深度 2，深层代码按需通过搜索工具探索）。
- **打开的标签页列表**：告知模型当前用户正在编辑或查看哪些文件。
- **工作区诊断（LSP 错误与警告）**：将当前打开文件中的语法错误、类型检查警告智能摘录进上下文，方便模型针对性修复问题。

## 4. 视觉模型与媒体预处理

GrayCode 支持向多模态模型发送本地图片、剪贴板截图以及 PDF 文档。

### DeepSeek Vision 专属预处理
针对 DeepSeek 等对图像分辨率、格式或长图有特殊要求的视觉模型，可在渠道设置中开启 **DeepSeek Vision 预处理**：
- **PDF 逐页渲染**：借助 `pdfjs-dist` 与 `@napi-rs/canvas`，将 PDF 逐页高精度栅格化为多模态图片发送，保留原始排版与图表。
- **GIF 动画拆帧**：自动将动态 GIF 采样为多帧序列图片，确保模型能观察到动图中的连续变化。
- **格式规范化**：自动将各类格式（如 WEBP/AVIF/TIFF/BMP 等）无缝转码为官方推荐的图像格式。
- **尺寸自适应**：在保留关键细节的前提下等比例适配至推荐像素预算，避免因超大分辨率被拒收。

> 相关可选依赖可在桌面的 **依赖管理** 面板中一键安装或更新。

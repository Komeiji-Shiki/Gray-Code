# 模型、图片与上下文

[返回目录](Home.md)

## 渠道与协议

渠道定义请求地址、凭据、模型、协议、工具模式、思考与上下文设置。当前直接模型适配包含以下格式：

| 格式 | 工具图片的发送方式 |
| --- | --- |
| OpenAI Chat Completions | 完整配对同批工具响应后，追加带工具归属说明的用户图片消息 |
| OpenAI Responses | 使用该协议的图片输入内容块 |
| Anthropic | 在支持的消息或工具结果内容中传递图片 |
| Gemini | 在内容部分中传递图片数据 |

启用多模态决定是否向选定渠道发送图片。工具本身生成截图、历史保存图片、模型请求包含图片，是链路中的三个环节。运行记录中的实际请求与图片计数可以检查最后一个环节。

原生函数调用、XML 和 JSON 工具模式按渠道能力选择。模型名称与兼容端点的行为变化较快，GrayCode 使用配置与实际响应，不依靠名称推断所有能力。

## 图片与请求前缀

新增参考图或工具截图时，已有图片继续保留在当前历史顺序中。应用已经移除“只发送最近 N 张图片”的数量设置。旧配置中的该字段不再限制请求。

~~~mermaid
flowchart LR
  A[系统提示与工具声明] --> B[已有消息与图片]
  B --> C[追加本轮消息与新图片]
  C --> D[协议格式器]
  D --> E[模型端点]
~~~

这让连续请求尽量保留相同的已有前缀。供应方如果支持提示缓存，可以复用符合条件的前缀，减少重复输入的计费或处理开销。实际命中取决于供应方、模型、缓存有效期和请求格式；本地图片计数不等于缓存命中率。

切换模型、修改系统提示或工具集合、切换历史分支、显式压缩上下文，都可能改变请求前缀。新增功能避免仅因又收到一张图而重写过去的消息。工具目录在任务开始时捕获；MCP 刷新影响后续捕获的目录，已有任务保留原声明。

图片完整保留不改变服务商自身的上下文和请求大小限制。遇到超限时根据实际错误选择模型或使用明确的上下文操作。

## 自动附带的工作区信息

“设置 → 上下文”决定每轮自动附带的目录、文件路径和诊断范围。它们会占用输入 token，文件正文仍由读取工具按需取得。

| 参数 | 默认值与特殊值 | 调整场景 |
| --- | --- | --- |
| 文件树深度 | 默认 2；0 仅根目录条目；-1 最多展开 100 层，仍有条目数量限制 | 大项目可降低以减少扫描和上下文；深层目录定位困难时提高 |
| 打开的标签页 | 默认最多 20 条路径；0 省略列表；-1 不限制 | 打开大量无关文件时降低，只影响附带的路径列表 |
| 每文件诊断数 | 默认 10；0 省略诊断；-1 不限制 | 同一文件有很多错误时提高，可看到更多线索 |
| 诊断文件数 | 默认 20；0 省略诊断；-1 不限制 | 集中修改少量文件时降低，也可选择仅打开的文件 |

计数只能为 -1 或非负整数。诊断被数量限制省略时会明确标注，零范围不代表文件没有错误。忽略模式控制自动附带的上下文，不改变文件工具本身的授权范围。

## 历史、分支与压缩

会话保存用户消息、模型内容、工具结果、附件和候选分支。编辑重试与重生成沿现有分支流程工作。原始历史保存在本地，模型运行使用当前选择的历史路径。

活跃运行读取历史时使用增量游标。没有变化时读取很小的版本响应；新增消息或尾部修改只更新相应部分。这是读取方式的优化，不减少逻辑历史或图片数量。

上下文总结与压缩按照配置和明确操作建立新边界。分支切换、恢复、回收或版本变化会使旧读取游标失效，并重新读取正确内容。

## 图片文件与特殊预处理

普通图片、工具截图与 PDF 附件走各自内容处理路径。DeepSeek Vision 专用预处理可按渠道启用，提供 PDF 栅格化、图片分块或压缩、GIF 拆帧与格式转换；所需组件在依赖管理中安装。其尺寸和请求校验属于该适配器的协议约束，与已经删除的历史图片数量设置无关。

依赖尚未安装或接口不支持某类媒体时，以当前错误信息为准。原始图片与处理后的请求内容可通过对应任务记录核对。

## 查看一次请求

打开运行记录，选择模型请求。可以查看当时协议正文、输入项数量、图片数量、原生工具声明数量，以及供应方返回的用量。旧请求没有新增计数时保持缺省。

诊断快照重建完整请求。存储对重复消息与工具对象做内容共享，不改写发送正文；因此快照结构优化不会自行改变模型端缓存前缀。

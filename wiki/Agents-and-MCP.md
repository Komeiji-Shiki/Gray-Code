## 工具目录

任务开始时捕获当时的工具声明、配置与校验函数。重复声明复用参数校验器；工具刷新释放当前目录中不再需要的缓存，已运行任务仍持有它开始时的版本。

当前保持固定的任务工具目录。没有默认加入每轮自动加载和移除工具的机制，避免在缺少收益依据时频繁改变请求前缀。新增 MCP 配置或启用外部代理属于明确的工具配置变更。

## MCP

在 MCP 设置中添加服务器，选择 stdio 或 HTTP 类传输，填写命令、参数或地址。保存配置后连接，查看实际发现的工具、资源与提示。stdio 程序的启动命令由本机执行；HTTP 服务使用配置的请求信息。

“连接与单次请求超时”以毫秒为单位，默认 `30000`（30 秒）。连接、每次工具调用、资源读取和提示读取分别使用这个上限。设置表单接受 `1000` 到 `300000`，耗时的搜索或分析工具可按实际耗时设为 `60000` 或 `120000`；较低的值能更快报告无响应，也可能中断仍在执行的请求。它不是整个模型任务的总时间限制。

“清理 Schema”控制发送给模型的工具声明，移除 Schema 节点上的 `$schema` 和 `additionalProperties`，用于处理模型接口拒绝这些字段的兼容问题。参数名称、引用、常量和示例内容保留。桌面执行器仍按服务器提供的原始 Schema 校验参数；关闭该选项后，模型也会收到原始声明。

MCP 工具未指定 `$schema` 时，按协议使用 JSON Schema 2020-12；显式声明的 draft-07、2019-09 和 2020-12 使用各自的校验器，避免新版约束被旧版忽略。参见 [MCP SDK 的方言说明](https://ts.sdk.modelcontextprotocol.io/v2/migration/upgrade-to-v2#behavioral-changes)。

平台使用 @modelcontextprotocol/client 2.0.0 处理新旧协议。旧初始化握手与 2026-07-28 协议在同一客户端边界适配，工具名称、账号、设置与历史仍由 GrayCode 管理。分页发现完成后整体替换目录，目录变更通知不会让一半更新的清单进入任务。

| 结果或事件 | 平台处理 |
| --- | --- |
| 正常工具结果 | 保存文字、结构化内容与附件 |
| 目录变化 | 刷新后供后续任务捕获 |
| 需要额外输入 | 保留 input_required 原始状态，显示尚未完成 |
| 连接中断、结果丢失 | 返回结果未知，不自动重复工具调用 |
| 取消与关闭 | 结束对应请求，清理本服务持有的连接与进程 |

现有名为 SSE 的配置继续使用 HTTP POST 与 SSE 响应语义；它不是对任意传统 GET /sse 服务的兼容保证。当前没有声明尚未实现的 sampling、elicitation 表单或 MCP Apps 宿主能力。MCP Apps 和动态工具发现留待有实际消费者和收益证据时接入。

## Skills

Skills 是带有说明与辅助资源的可复用工作流程。项目、共享与用户技能按现有来源加载，模型通过技能工具读取具体内容。技能的可用性与启用状态在设置和工具目录中查看。

程序数据备份与项目技能分别管理：项目内技能随项目源码保存，共享目录的技能不等于应用管理的本地技能副本。

## 原生子代理与团队任务

原生子代理使用 GrayCode 的模型与工具执行器，可以前台等待或后台继续。任务捕获启动时的模型、工具和工作区配置。后台完成结果带着原任务身份回流，已有完成状态和投递记录用于避免重复反馈。

团队任务支持依赖、领取、版本、消息与事件等待。等待其他成员时释放对应并发席位，避免单并发配置下父子互相等待；取消清理等待订阅。没有可推进工作时返回明确状态。

“设置 → 子代理”中的几个上限分别控制不同阶段：

| 配置 | 当前默认值与影响 | 调整场景 |
| --- | --- | --- |
| 最大并发数 | 3，同时运行的子任务数，其余排队 | 设为 1 可减少同时发出的请求；独立任务较多时可调高，同时也会增加资源占用 |
| 默认迭代次数 | 80，每个子任务的模型与工具执行轮数，一轮可能包含多个工具 | 多步骤任务可调高，单次短任务可设较低上限；次数不等于运行秒数 |
| 排队超时 | 600 秒（10 分钟），等待执行席位的时间 | 并发较低、已有任务较长时可调高，不计入开始后的运行时长 |
| 默认最大运行时间 | 1800 秒（30 分钟），自定义子代理未覆盖时使用，包含模型和工具等待 | 长任务可调高；单个子代理的输入框留空可恢复继承 |
| 通用 Worker 默认时长 | 2400 秒（40 分钟），可由用户修改 | 例如 `7200` 为 2 小时；主模型可在单次派发中用 `maxRuntime` 覆盖 |

以上配置都允许 `-1` 表示不限制对应项目，其他限制仍独立生效。General Worker 的运行时长按“本次 `maxRuntime` 参数 → 用户设置的通用 Worker 默认时长 → 初始值 2400 秒”确定。`maxRuntime` 接受正整数秒数或 `-1`，只覆盖这次派发，不改写用户配置。接续已结束任务时也可指定。正在执行的任务保留启动时捕获的上限。

## 外部 ACP 编码代理

在“设置 → 开发 → 外部编码代理”配置支持 ACP 的程序。每项包括名称、启用状态、启动命令、独立参数列表和可选环境变量 JSON。保存配置不会立即启动程序。

Kimi Code 示例：

| 字段 | 值 |
| --- | --- |
| 启动命令 | kimi |
| 参数 1 | acp |
| 环境变量 | 按已有本机配置需要填写 |

其他程序使用其官方 ACP 入口。例如 Claude 的 ACP 适配器需要先按[适配器项目](https://github.com/agentclientprotocol/claude-agent-acp)安装并完成登录，再填入对应启动命令。Codex App Server 使用另一套线程与回合协议，本版未实现专用适配器；不能把普通 codex 命令直接当作 ACP 程序。

模型通过 coding_agent 工具使用会话：

| action | 行为 |
| --- | --- |
| list | 查询已启用配置和当前任务的代理会话 |
| create | 在任务工作区启动程序并创建会话，可同时发送第一条提示 |
| prompt | 向已有会话追加新提示，可附带工作区相对图片路径 |
| load | 明确恢复已保存会话，优先使用代理提供的 resume |
| fork | 按代理声明的能力派生独立会话 |
| configure | 使用代理返回的模式或配置 ID 调整会话 |
| events | 从给定序号读取已保存事件，每页最多 100 项 |
| close | 关闭本会话持有的程序，保留历史 |

每个会话持有独立进程，连续提示复用它。初始化、会话设置等请求有超时；停止提示先通知代理取消，无响应时关闭对应连接和进程。应用重启保留会话记录，未完成操作不会自动重放。

会话恢复后读取代理返回的模型、模式与配置。旧历史的回放不追加成新的模型输出。图片只随本次新增输入发送，之前的图片由外部代理会话继续保留。

代理权限请求显示原始操作和具体选项，包括单次或持续允许/拒绝；返回原选项 ID，不将所有选择压缩成一个布尔值。聊天、子任务、远程任务、CLI 与 Bot 共用此确认契约。需要表单、客户端托管终端或文件服务的能力尚未声明，程序使用自己支持的执行方式。

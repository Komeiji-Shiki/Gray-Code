# 性能与验证

[返回目录](Home.md)

记录对应 2026-09-21 开始的改进批次。数值来自同一 Windows 机器上的合成夹具，目的在于比较相同模块和负载的前后变化。

## 测量结果

| 场景 | 前后结果 | 测量条件 |
| --- | --- | --- |
| 文件树 | 挂载与布局中位数 787.5 → 21.8 ms；DOM 40,011 → 204 | 8,000 条目，真实 Electron 页面；修改后 38 个渲染行 |
| 活跃历史 | 完整读取约 99 ms；未变化增量约 0.22 ms/385 B；追加约 0.28 ms/453 B | 8,000 条消息，逻辑历史约 5.36 MB，重建结果一致 |
| 向量混合检索 | 中位数 108.84 → 66.17 ms | 8,000 条、768 维，保持精确排序 |
| 检索期间独立小读取 | 中位数 113.96 → 37.90 ms | 与上述检索并发 |
| 请求快照对象总量 | 12,545,269 → 1,094,139 B，减少约 91.3% | 100 份逐渐增长请求，210 条消息和 10 张合成图片 |
| 请求快照数据库文件 | 12,660,736 → 2,502,656 B | 相同请求夹具 |
| 请求快照写入 | 中位数 5.42 → 4.44 ms | 相同请求夹具 |
| 最后一份完整快照读取 | 约 10 → 22 ms | 热读取，恢复完整内容 |

最后一项是明确取舍：去重减少存储和写入，但完整诊断读取需要展开引用。正常会话历史使用增量路径，不依赖每轮重建请求快照。

## 已执行的针对性验证

- 工具参数校验复用、目录替换与旧任务继续运行。
- 受管进程结束、取消、错误退出与结果回收。
- 多协议真实本机 HTTP 图片请求、完整历史图片和稳定前缀。
- Electron 浏览器 100%/125% 缩放下的截图、坐标点击、中文输入、组合键、拖动与操作回执。
- 大目录虚拟化、键盘导航、批量局部刷新和移动端行高。
- 增量历史重建、尾部修改、分支/恢复失效；精确向量排序与存储队列顺序。
- 请求快照旧格式读取、版本升级、重启、附件引用、删除回收与选择性备份恢复。
- MCP 新旧 stdio/HTTP、分页、目录更新、取消、input_required 与未知执行状态。
- ACP 真实子进程会话、连续权限选项、图片输入输出、配置/模式、恢复、派生、取消与断线不重放。
- 本机隔离节点的实际 TLS 配对、断线、撤销、任务和电脑操作去重；Bot 和自动任务使用可控端点。

完整类型检查通过。后端 293 组、3,230 项通过，另有 2 项既有跳过；前端 138 组共 1,177 项，初次有 1 项静态守卫误扫测试样本，修正后相关 12 项通过，其余 1,176 项已在完整运行中通过。平台 86 组、339 项通过，TypeScript/Python 提示词引擎和国际化一致性检查也通过。未因为一次测试误报重新执行已经通过的全部阶段。

真实 Electron 工作台通过发送、重生成确认、编辑重试、工具确认、文件树与编辑器、运行请求预览、工作树“新建任务”和原草稿恢复。Windows 原生宿主对测试窗口按截图坐标点击，使用同一操作身份重试后实际只点击一次。

浏览器额外验证 iframe 坐标点击、可见/后台切换、人工接管后允许自动操作、任务结束后重新截图与滚动。实测发现滚动后过早截图会返回旧位置，等待新绘制帧后，返回观察与实际滚动位置一致。桌面实测还发现沙箱预加载无法加载外部工作区依赖，已将纯契约代码打入预加载并加入构建检查。

## 验证边界

本次不安排数小时或数日观察。合成端点接收图片能证明请求传递正确，但不代表某个外部模型已经正确识别图片。实际 Kimi/Claude 登录账号、真实 Bot 频道、双设备、手机软键盘、混合 DPI 和多屏组合仍取决于部署环境。

性能测试没有调用付费模型，不把输入体积减少或本地缓存命中转换成供应方费用承诺。图像历史完整保留，实际收费以供应方报告为准。

## 2026-09-22 补充测量

聊天渲染改为遇到公式或带语言标注的代码块时加载对应库。使用同一源码构建方式，启动所需 JavaScript 减少约 16%；普通 Markdown 组件从约 992 KB 降至 24 KB。KaTeX 和完整高亮语法仍随应用分发，变化是加载时机，安装包总量不按这个比例减少。

27 项消息与 Markdown 渲染回归通过。隔离的真实 Web 页面验证了公式、TypeScript 和 Mathematica 渲染，无浏览器错误。另一项 MCP 重复 JSON 样本基于本项目 47 个组件文件名构造，按 cl100k_base 计数由 2193 降至 740 tokens；检查确认仅移除重复文本副本，其余结构化字段不变。这是该样本的结果，不代表所有对话都减少相同比例。

终端声明按当前可选 Shell 组织差异规则，共用 POSIX 说明合并一次，工作目录规则集中在参数定义。Windows 默认配置下，cl100k_base 对完整 execute_command 声明计数从 3396 降至 2344 tokens，约减少 31%；隔离实例的 75 项工具目录从 26426 降至 25374 tokens。保留了各 Shell 引号和管道、MSYS/WSL 路径、SSH 多层解析与后台完成通知说明。中英文声明 4 项及终端执行回归 20 项通过。

## 保留与省略的结构

MCP 重复协议解析与连接包装已由官方 SDK 和单一客户端边界替换。RPC 从截图、文件、设置和任务领域开始共享类型与入口校验，旧动态领域继续使用既有入口。

成熟聊天 iframe 和两个 Vue 根继续保留；状态问题沿具体桥接修复。共享 backend 模块仍有真实调用者，未为目录外观整体搬迁。MCP Apps 尚无当前消费场景，动态工具发现缺少净收益依据，因此本次没有额外引入对应宿主和目录切换机制。

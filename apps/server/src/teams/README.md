# 团队协作

`team_tasks` 和 `team_wait` 复用平台运行器、工具权限和 SQLite 工作线程。默认 Agent 自动获得内置工具；自定义 Agent 的工具范围及显式禁用保持有效，通用子代理继承父任务实际拥有的工具目录。

## 任务领取与依赖

团队范围由认证运行的主会话推导，工具参数不能指定另一个团队。成员身份为主代理 `main` 或稳定的子代理 ID；领取另外保存当前 `ownerRunId`，防止重试或接续后的运行提交旧结果。

- `create`：保存标题、说明与已存在任务的依赖 ID，验证自依赖与间接循环。
- `list`／`get`：分页读取简要状态或单个任务详情，返回当前事件 `sequence`。
- `claim_ready`：在事务内领取最早创建、尚未领取且依赖已全部完成的任务；没有合适任务时返回 `task: null`。
- `claim`／`complete`／`release`／`set_dependencies`：必须提供当前 `expectedRevision`。完成仅限领取的当前执行；释放允许当前负责人或主代理；依赖仅能由创建者或主代理在待领取状态修改。

任务状态、版本、负责人、执行轮次和事件一起提交。每个主会话使用短事务队列，队列中不等待模型调用或团队事件。缓存只在提交成功后更新。失败、取消、暂停、重启不会自动释放或重新运行任务；主代理可以明确释放后安排新的执行。释放任务状态不会停止旧执行或锁住文件，重新分派文件工作前应先停止旧执行。

## 等待事件

模型将最近收到的 `sequence` 传给 `team_wait.afterSequence`。服务先读取已经发生的变化，再注册等待，二者与提交共用主会话队列，避免漏掉读取和订阅之间的事件。结果每页最多 50 条，`hasMore` 表示继续用返回的 `sequence` 读取。

任务变更、消息入队和成员状态变化会唤醒订阅。等待使用一次超时定时器，不循环查询。默认等待 30 秒，最多 60 秒，可用 0 立即检查。`readyTaskIds` 提示可以领取工作，`noProgress` 表示当前没有就绪任务或其他能推进的成员，应处理阻塞、报告情况或结束，避免重复空等。等待审批、输入、暂停、失败或已经等待其他任务的运行不会被计为可运行成员。

子代理等待时释放并发席位，等待结束后按原 FIFO 队列重新获得席位；取消会清理等待者。前台父子等待使用同一机制，使主代理被子代理阻塞时不会被误判为正在推进。

## 持久顺序

`team-state` 保存主会话序号；`team-tasks` 保存各任务；`team-events` 按主会话及补零后的序号建立记录 ID。事件读取复用 `records(namespace, owner_id, id)` 索引的游标分页，不反复枚举历史事件。

反馈队列、发送回执、消息序号和对应事件一起保存。新消息按序号交付，同一毫秒和随机 ID 不影响先后；重复接收沿用第一次提交，重启继续递增。历史未编号消息保留旧排序并先于新增消息处理。本次没有改变已有消息积压上限或加入新的批次输入预算。

## 验证

`packages/core/tests/teams.test.ts` 使用隔离模型、真实平台运行器与 SQLite，覆盖竞争领取、依赖／循环、负责人和执行版本、跨主会话隔离、事件补读及分页、订阅边界、取消、无进展、单并发席位释放、消息幂等和重启恢复。没有连接真实模型、机器人，也没有将功能测试作为吞吐量基准。

# 独立任务的上下文管线

`PlatformRuntime.prepareModel` 在每次真正调用模型前交给 `PlatformContextService` 处理。输入是同一次存储读取获得的历史和元数据；返回模型可见历史及提交后的版本，后续模型结果使用这个版本追加。上下文处理不会改变任务开始时固定的工具目录或认证身份。

## 共用逻辑

原 `TokenEstimationService` 的本地算法提取到 `MessageTokenEstimator`；原 `SummarizeService` 的预算、清洗、提示词、统计和范围辅助提取到 `SummaryAlgorithms`。原扩展服务继续继承这些实现。上下文评估、回合边界、工具配对检查和请求级裁剪继续调用原 `contextTrim` 模块。

`CapturedContext` 实现这些服务实际需要的状态接口，将 Token 计数等修改暂存在一次读取的快照内，最后使用 `commitConversation` 一起提交。不使用伪造的 VS Code 对象，也不让旧服务绕过新存储直接写 JSON。

可选媒体依赖通过 `backend/modules/dependencies/runtime.ts` 提供。VS Code 宿主注册原 `DependencyManager`；独立宿主已经接入应用级依赖管理与运行时作用域。具体图片/PDF 能力取决于当前安装和渠道配置，缺失依赖时明确返回不可用。

## 当前行为（2026-09-10）

- 自动方式在每个模型渠道的上下文管理区域选择，保存为 `autoSummarizeMethod`；手动方式使用全局 `SummarizeConfig.method`。未单独配置的旧渠道沿用全局方式，选择后独立保存；Bot 的显式方式继续优先。渠道切换协议、配置导入导出和重启都会保留自动选择。
- 运行开始时根据实际所选渠道捕获自动方式与工具目录。保存新方式只影响后续回合；手动笔记换窗口后，即使渠道的自动方式是普通总结，仍提供笔记和历史恢复工具，不要求两种选择相同。

- 普通总结复用当前模型、系统提示词、工具定义、动态上下文与会话标识，在完整活跃历史末尾追加用户角色总结指令。指令不构成新用户回合，成功后仅保留首条真实用户消息和新摘要。上一条摘要也由新边界替代；原文与附件完整保存。长任务的新窗口积累了模型历史后，可以再次总结。
- 笔记换窗口提供 `context_notes`、`context_history` 和 `new_context`。达到渠道阈值时追加提醒，模型保存笔记后在完整工具批次结束时换窗口。新窗口保留首条用户消息、笔记索引和最新请求的历史定位信息，按需恢复旧消息与工具结果；原图需显式请求，并遵守渠道多模态工具配置。手动操作直接换窗口，不额外请求整段摘要；超过硬输入预算时可直接切换，依靠已保留历史恢复。
- 方法和工具目录在回合开始时共同捕获，设置变更不改写运行中任务的前缀。普通总结不再使用保留一半、最近 N 轮或专用总结模型设置；失败和取消不会覆盖原文，也不会静默改为部分历史总结。稳定前缀通过实际 HTTP 请求比较验证，缓存是否命中仍由供应方决定。
- 两种方法共用可恢复边界和事务提交。笔记与历史工具只访问当前已授权会话，支持持久笔记、分段读取和稳定消息／窗口 ID。该方式参考 Codex 的[实验性上下文管理](https://learn.chatgpt.com/docs/models?surface=app#experimental-context-management)和 [history/notes 实现](https://github.com/openai/codex/pull/39827)，由 GrayCode 本地实现，不使用加密 compaction 接口。
- 手动总结、取消总结和按稳定消息 ID 恢复总结已连接原界面协议。原始消息和分支正文保留，分支切换时按该路径实际包含的总结重新计算覆盖标记。
- 总结开始、完成、失败和临时裁剪写入任务事件，原自动总结状态与消息组件接收对应通知。

## Bot 与模型输入边界

Discord／OneBot 可单独选择普通总结、笔记换窗口或原有时间总结。旧设置缺少方法字段时仍使用时间总结，保留时间规则、比例、提示词和已配置的总结模型；常规方式使用渠道阈值，时间检查不会误触发它们。

TXT／MD 文档及引用、转发中的同类附件先保存原始字节，模型只接收名称、大小、本地路径和读取入口。`bot_read_attachment` 默认每次读取 4,000 字符，最多 12,000 字符，支持偏移量续读。文档下载上限 32 MiB，图片保持原有 12 MiB 上限，工具不能读取其他会话的附件。

Discord 显示用思考完成提示、耗时、Token 和 TPS 在渲染时生成，不写回原始模型消息。API formatter 只发送 `role` 和 `parts`；控制标记、统计和界面专用正文均被移除，真实思考与签名按原渠道设置处理。

应用测试覆盖完整前缀、渠道自动与全局手动选择的独立性、运行中设置变化、配置导入导出与重启、重复恢复、笔记持久化、换窗口后继续执行、历史和图片恢复、文档分段读取、Bot 方法选择及逐轮输出。供应方原生格式的工具配对与附件回归单独验证。测试使用本地存储及虚拟模型、网关，不表示已经完成真实 Discord 与模型服务的端到端验证。

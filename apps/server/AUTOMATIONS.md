# 长期目标与定时任务

桌面左侧的“自动任务”和手机顶部“更多 → 自动任务”共用同一管理面板。创建时选择长期目标或定时任务，填写目标、关联对话、模型、预设和可选的 Token 总预算。也可以为任务创建独立对话与工作区。

长期目标在一轮模型任务正常结束后继续推进，直到模型报告完成、需要用户信息、运行出错、达到预算，或主人手动暂停。`goal_update` 只加入当前目标主任务的工具目录，完成报告在本轮工具结果保存之后生效。目标重启后保留目标、进度、历史和用量，等待主人手动继续。

“暂停后续执行”允许当前这轮结束；“停止当前执行”同时停止属于该目标的当前运行与后台子任务。普通消息开启新的手动运行时，同一对话中的自动执行会暂停。移除自动任务会停止相关运行，对话和历史保留。

暂停且当前运行结束后，可以编辑目标、模型、预设、预算和定时规则。保存更改后继续保持暂停，已有用量和进度保留；点击“继续”才重新执行。任务类型及关联对话在创建后保持固定。

Token 预算累计每次模型请求的输入与输出，包括内部总结、操作审核和子任务。缓存命中是输入的细分，不重复累计。缺失或不完整的供应方用量使用本地估算并单独标记；失败请求的最终上游用量无法确认。达到预算后不再发起新的模型请求，已经进行的请求可能使总量超过预算。暂停后可以增加或取消预算再继续。

定时任务支持一次、分钟间隔、每天和指定星期。每天与每周按所选时区计算；分钟间隔保留首次执行时间的节奏。创建时必须明确选择应用关闭期间错过时间后“跳过”或“补一次”，不会逐次补跑。上次运行在退出时中断，需要确认已有结果后手动继续。

触发标记和新运行写入同一个会话事务，同一个触发不会因并发调度重复创建任务。后台回报由原自动任务继续处理，保留模型配置、工作区和预算归属。执行继续使用已有运行器、工具权限、人工确认、上下文总结、Bot 和聊天事件链路。

数据保存在程序数据库中，包含在程序数据备份内。定时任务需要 GrayCode 核心保持运行；启用中的自动任务会让关闭主窗口后的核心留在后台，明确退出应用时一并停止。

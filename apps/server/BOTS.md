# Bot 接入

Discord 与 OneBot 共用会话路由、平台身份绑定、工具审批、异步问题和待发送消息记录。平台事件提供的用户 ID 才用于身份解析；昵称、群管理员身份和引用文字不授予 GrayCode 权限。配置保存与连接分开操作，保存设置不会自动登录 Bot。

## NapCat 与 OneBot 版本

NapCat 官方当前提供 OneBot 11 接口；OneBot 12 官网仍标为候选标准。两种协议分别适配，共用 WebSocket 连接、重连和请求关联逻辑。设置页选择 NapCat 时使用 OneBot 11；仅在对端实现明确支持 OneBot 12 时选择 v12。

- [NapCat 官方接口文档](https://napneko.github.io/api/)
- [OneBot 11 正向 WebSocket](https://github.com/botuniverse/onebot-11/blob/master/communication/ws.md)
- [OneBot 12 标准](https://12.onebot.dev/)
- [OneBot 12 动作请求与机器人身份](https://12.onebot.dev/connect/data-protocol/action-request/)

当前接入方式为正向 WebSocket：GrayCode 主动连接 NapCat 或其他 OneBot 实现提供的通用接口。地址和访问令牌分别填写；配置中的令牌使用平台密钥存储加密。没有配置鉴权的本地实现可以不填令牌。程序不会安装 NapCat、登录 QQ、修改其服务配置，或自行开启反向 WebSocket 监听。

v11 的允许会话格式为 `group:群号`、`private:QQ号`。v12 另支持 `channel:群组ID:频道ID`，并要求显式填写机器人的 `platform` 与用户 ID，避免共享连接中选错账号。v12 ID 中如包含冒号等地址分隔符，需要做 URL 编码。平台身份绑定也包含平台标识，避免不同平台上相同用户 ID 共用权限。

收到的图片、TXT／MD 附件以及引用、合并转发内容会按平台能力读取。QQ 的文字、图片和引用保留原消息段顺序；附件最多三个并行下载，重复消息在下载前去重。TXT／MD 保存为可按范围读取的本地文档，正文不会直接塞进模型上下文；不支持的附件保留说明。

回复的文字仍使用文本消息段，不执行模型输出中的 CQ 码。模型生成的图片可直接发回原会话；启用工具的 Bot 任务还提供 `bot_send_attachment`，可发送当前账号有权读取的本地图片或文件，最大 32 MiB。该工具沿用文件读取授权与 `external_send` 工具审批，发送目标由原任务固定，同一次调用重试复用发件箱记录。

新建 QQ 配置默认把超过 1900 字的回答作为合并转发发送，也可选择文字分段或文档。已有配置缺少输出字段时继续使用文字分段。OneBot 12 使用标准文件上传与消息段，不提供合并转发，需选择分段或文档。

## 群聊触发与排队

Discord 与 QQ 均支持提及 Bot、回复 Bot、提及或回复、关键词、所有消息和仅指令，可按频道或群覆盖默认设置。`/gray` 控制指令独立于提及开关，仍要求当前账号获准。回复触发需要能确认被引用消息的作者；OneBot 12 对端未提供原文时无法由通用历史接口补查。

新配置的群聊消息策略为：同一人的连续消息合并窗口 1 秒，同一人在同一群启动下一轮回复至少间隔 3 秒，每群最多排队 20 条触发消息。合并窗口不因后续消息到来无限延长，冷却期间保留消息等待，超过上限的消息保留为群聊背景但不单独安排回复。三项均可按群调整，0 表示关闭；私聊即时处理。旧配置缺少这些字段时继续保持原节奏。

每条原消息独立归档，合并只改变交给模型的当轮输入。停止、状态查询、审批和问题回答可以先于慢附件处理；新建或切换会话、工作区的指令继续按消息顺序执行。

## 任务与操作

允许会话中的已绑定用户可以发送任务，或使用以下命令：

- `/gray new`：新建对话。
- `/gray task 对话ID`：选择可访问的已有对话。
- `/gray status`、`/gray cancel`：查看或停止当前任务。
- `/gray answer 提问ID 回答`：答复问题；多个回答用 `|` 分隔。
- `/gray approve 审批ID`、`/gray deny 审批ID`：处理属于当前会话的审批。

任务仍经过核心账号权限检查。Discord 同时处理旧会话恢复与重新登录后的就绪事件。OneBot 断线后使用延迟重连，重新连接时核对机器人身份；身份变化需要手动重新连接。收到心跳后按对端声明的间隔检测连接，连续三个间隔没有心跳时重新连接；未启用心跳的对端保持正常接入。QQ 账号离线与 WebSocket 连接状态分别显示。

发件箱在同一频道内按顺序处理，最多四个频道并行发送。平台明确拒绝的消息显示具体原因，确认尚未发送的临时错误自动延迟重试；发送后回执丢失仍保留为“结果未确认”，检查会话并确认重复风险后才能重试。重试使用保存的回复，不重新调用模型。Discord HTTP 限流由 SDK 处理。

## 消息诊断

Bot 设置页的“消息诊断”显示最近 100 条消息的处理阶段、耗时与原因，并能检查指定平台用户在指定会话中是否可以发起任务。诊断记录保留在内存中，重启清空；完整历史、发送记录与账号权限仍使用原有持久化存储。只有主人可以查询这些管理接口。

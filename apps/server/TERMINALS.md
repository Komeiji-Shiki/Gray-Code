# 独立平台终端工具

`execute_command` 已接入独立工具目录。进程启动、Shell 参数、Windows 输出编码与 GBK 回退、输出截断、超时、进程树停止以及前台转后台复用原终端实现。原 VS Code 入口保留为宿主适配器，独立服务不导入 VS Code 或扩展的全局任务管理器。

每次调用捕获当前 Shell 配置并绑定当前任务、账号、对话和工作区。工具声明使用已启用的 Shell 配置，避免目录内容因临时可用性检测而变化；实际执行前检查所选 Shell。工作目录在当前任务工作区内解析。Shell 本身仍具有执行账号的操作系统权限，工作目录约束不等同于进程沙箱。审批沿用原工具设置和核心执行规则。

前台命令接收当前运行的取消信号；显式后台命令及通过聊天队列转入后台的命令不再受父运行取消或前台超时影响。它们可以从原输出卡片、后台任务条或 `terminals.stop` 接口停止。终止范围来自保留的进程对象，不接受任意 PID。

`terminal-records` 保存命令归属、状态和最终输出，`terminal-active` 保存需要恢复处理的记录索引。启动时把无法继续观察的原进程标为中断，不自动重放。后台结果先进入持久化队列，再在模型边界或对话空闲时追加历史；界面只更新任务条，不重复发送一份用户输入。子代理已结束时，其后台命令结果返回主对话。关闭窗口会把后台命令纳入托盘留驻判断，最后一项任务结束后继续原来的退出规则。

当前限制：流式输出保留在运行器内存中，进程结束后保存最终输出；异常断电前尚未结算的输出不保证恢复。空闲对话收到后台结果后会更新历史，自动启动模型总结仍未接入。本次只完成代码迁移与本地提交，遵照用户要求没有执行测试、类型检查、构建或真实命令联调。
